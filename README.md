# ConstructIQ — AI Construction Timesheet Audit Agent

Built for the **Google Agent Builder Hackathon 2026 (MongoDB track)**.

ConstructIQ ingests HCSS HeavyJob daily timesheet exports (PDF or scanned
image), checks every worker and equipment line against project baselines, and
returns a ranked, plain-English audit report — turning a manual line-by-line
review that takes a project manager 20-30 minutes into a < 30 second
automated pass.

## Features

- **Document ingestion**: HCSS HeavyJob timesheet PDFs/screenshots are parsed
  via **Reducto Extract** into structured worker/equipment rows, then
  normalized into a canonical schema (handles HCSS's `"8/2.5"` ST/OT cell
  format, equipment sub-rows, etc.).
- **Four-layer anomaly detection**:
  - *Missing values* — required fields absent (e.g. no straight-time hours)
  - *Categorical anomalies* — wrong labor class for a cost code, wrong
    equipment for a cost code, wrong operator class for an equipment type
  - *Equipment standby* — equipment hours logged with no matching operator
    hours (idle/unauthorized billing)
  - *Numerical outliers* — an IsolationForest model (trained and served on
    **Vertex AI**) flags hours that fall outside the historical baseline for
    a cost code / labor class combination
- **Gemini-powered narration**: every flag's rule-generated explanation is
  rewritten in plain English by **Gemini 2.5 Flash (Vertex AI)**, plus a
  one-paragraph executive summary of the whole audit. Flag count in == flag
  count out is a hard invariant — Gemini narrates and ranks, it never
  invents or drops findings.
- **Streamlit dashboard**: severity-coded (red/amber/grey) flag cards, ranked
  high → low, with observed-vs-expected detail for each finding.
- **MongoDB Atlas**: stores per-cost-code/labor-class baselines, ingested
  timesheets, and every generated audit report.

## Tech stack

| Layer | Technology |
|---|---|
| OCR / document extraction | Reducto Extract |
| Detection (rule-based) | Python — missing-value, categorical, and equipment-standby checks |
| Detection (ML) | scikit-learn IsolationForest, deployed to a Vertex AI online endpoint |
| Reasoning / narration | Gemini 2.5 Flash via Vertex AI |
| Database | MongoDB Atlas (`timesheets`, `baselines`, `audit_reports`) |
| API | Flask (`api/routes.py`), containerized for Cloud Run |
| Frontend | Streamlit |

## Data sources

- Real HCSS HeavyJob baseline structure (cost codes, labor classes,
  equipment-to-cost-code pairings) modeled from an actual project
  (Westmorland Elementary School, project `31062-00`).
- A 200-day / 12-worker synthetic timesheet dataset (3,829 records) with
  labeled ground-truth anomalies, generated by
  `scripts/generate_synthetic_data.py`, used to train the IsolationForest and
  power the in-app demo.

## Running locally

```bash
pip install -r requirements.txt
cp .env.example .env   # fill in MONGODB_URI, GOOGLE_CLOUD_PROJECT, etc.
python3 scripts/seed_mongodb.py
python3 scripts/generate_synthetic_data.py
streamlit run frontend/app.py
```

Click **"Use sample timesheet"** for an instant demo, or upload an HCSS
PDF/PNG to audit real data.

## Findings & learnings

- **Hybrid rule-based + ML beats pure ML for this domain.** Structural
  anomalies (missing fields, mismatched categories, standby equipment) have
  deterministic rules with ~100% recall and need no training data; only
  multivariate "hours outside the norm" patterns benefit from a model.
- **Bounding the LLM payload matters for live demos.** Sending every detected
  flag to Gemini for narration in one prompt does not scale — on the full
  synthetic dataset it produced 400+ flags in a single request and caused
  multi-minute hangs. Capping the narration payload to the top N flags by
  severity (while always returning the full flag list) keeps latency
  bounded without sacrificing the report's completeness.
- **Real HCSS screenshots work end-to-end through Reducto Extract** with no
  changes beyond enabling `array_extract` — validated against an actual
  timesheet image, not just synthetic data.
